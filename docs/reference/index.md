# Reference

Lookup material: every exported symbol, every level, every exit code, every log field
the handler emits, and the things the package deliberately does not do.

The pages here describe **observed behaviour of the current release**, checked against
the source rather than restated from the design intent. Where the two differ, the
behaviour is what is written down.

## Which reference page answers which question

| You want to know | Page |
|---|---|
| What a function or type does, and what it does with bad input | [API reference](api.md) |
| What each level logs, and whether it exits | [Report levels](levels.md) |
| Which exit code the process actually uses | [Exit codes](exit-codes.md) |
| What the fields in a log line mean | [Log fields](log-fields.md) |
| Whether something is supported at all | [Limitations](limitations.md) |

## Why generated Go docs are not enough

[pkg.go.dev](https://pkg.go.dev/gitlab.com/phpboyscout/go/errorhandling) carries the
signatures and the doc comments, and it is the right place to look up a parameter
order. What it cannot show is behaviour that emerges from how the pieces combine — the
exit code a special error uses in preference to the one you attached, the fields a
report drops on the special-error path, the hint that survives one kind of wrapping and
not another. Those live here.
